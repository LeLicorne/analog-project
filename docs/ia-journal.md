# Journal : code généré, relu, testé

Ce projet a été construit avec un agent de code (Claude Code). Ce journal recense **ce que l'IA a produit de faux ou de risqué, comment cela a été découvert, et le garde-fou ajouté**. Il sert de preuve de la démarche : comprendre, relire et tester systématiquement le code généré, sans lui faire confiance par défaut.

## Les règles qui en découlent

1. **Un agent qui dit « aucun doute » n'a rien prouvé.** Les agents qui ont rédigé 360 questions ont tous déclaré ne douter d'aucun fait ; trois liens étaient pourtant cassés. On vérifie par un contrôle indépendant (`bun run check:links`), pas par la confiance.
2. **Chaque affirmation a son test.** Une phrase affichée au public (« liens vérifiés automatiquement », « WCAG AA ») doit être vraie le jour où elle est écrite, sinon elle est retirée ou reformulée.
3. **Un test qui n'a jamais échoué n'a rien démontré.** Les tests e2e ont tourné pendant des jours sans le rendu serveur, sans que rien ne le signale.
4. **On corrige à la source.** Pas de boucle de relance, pas de `skip`, pas de règle désactivée pour faire passer un contrôle.
5. **Toute modification automatique doit prouver qu'elle a eu lieu.** Plusieurs remplacements de texte par script n'ont rien remplacé (le texte avait été reformaté) sans le dire : le résultat est relu.

## Ce que l'IA fait bien, et ce qu'elle ne fait pas

- **Bien** : mise en place rapide d'une structure cohérente, tests de cas limites, recherche d'une cause quand on lui donne les journaux, documentation.
- **Pas** : mesurer elle-même la fiabilité de ses affirmations ; remarquer qu'un test ne teste pas ce qu'il prétend ; signaler qu'une modification n'a rien changé ; connaître l'état réel d'une version récente d'un outil (Angular 22, Zod 4, SDK Firebase 13) sans lire ses types.

## Les mécanismes mis en place pour l'agent

- `AGENTS.md` : commandes, structure, règles de code, pièges déjà rencontrés, définition de « terminé » (`bun run check` vert).
- Skills de projet (`.claude/skills/`) : `quizz-new-page` (ajouter une page sans rien oublier), `quizz-a11y-review`, `quizz-seo-geo-check`, `quizz-security-review` (relectures avec preuve exigée, jamais « conforme » sans test).
- `.github/pull_request_template.md` : case « j'ai relu et je peux expliquer chaque ligne ».
- Garde-fous automatiques : ESLint strict, TypeScript strict, `ngc`, tests e2e qui échouent sur une erreur JavaScript ou une violation de CSP, analyse statique des secrets et des API dangereuses.
